## C. 构建与签名决策

### C1/C2 签名(已完成)
- Keystore:`proresforge-release.keystore`,alias `proresforge`,RSA 2048,
  validity 10000 天;证书 SHA-256 指纹
  `7A:40:D4:FC:75:F4:BD:4E:B4:DE:A6:45:58:4A:DF:69:43:73:76:0F:0E:59:57:CF:59:A1:1B:08:74:6B:F6:1D`。
- **保管位置(全部在库外)**:① WSL `~/keys/proresforge-release.keystore`;
  ② WSL `~/keys/backup/`;③ Windows `C:\Users\Administrator\ProResForge-signing\`。
  口令记录在与 keystore 同目录的 `proresforge-signing-info.txt`(不在仓库、不在
  任何构建脚本里)。**丢失 keystore 即无法向已安装用户推送升级——请立即把上述
  两个位置各自再做一份离线备份(密码管理器/U 盘)。**
- 构建接线:`app/build.gradle.kts` 的 `signingConfigs["release"]` 从根目录
  `keystore.properties`(**gitignored**,仅存在于构建机 `~/prf/`)读:
  ```
  storeFile=/home/ubuntu/keys/proresforge-release.keystore
  storePassword=…
  keyAlias=proresforge
  keyPassword=…
  ```
  文件缺失时构建照常,但产出**未签名** APK(供存档/CI)。
- 换新构建机:恢复 keystore + 新建 `keystore.properties` 即可,无需改任何入库文件。

### C3 minify(决策:不开 R8)
维持 `isMinifyEnabled = false`,理由已写入 `app/build.gradle.kts` release 块注释:
本地工具类应用无混淆收益;开 R8 需先补 JNI keep 规则(FFmpeg native 方法、
JNI 反射触碰类、JobSpec/JobRecord 序列化字段)并重跑全套设备冒烟——Round10
既定结论"没有冒烟不开 R8",1.0.0 不做这笔风险投入。代价:APK ~62MB(见 E2
的体积说明)。将来若开 R8:独立变更 + 重跑 D 段全套。

### C4 版本号(定稿)
`versionCode = 1`,`versionName = "1.0.0"`(`app/build.gradle.kts`)。
规则:以后每次对外分发(含同一版本的重发修复)**必须递增 versionCode**。

### C6 渠道形态(决策:GitHub/官网直发 APK)
选择**自签 APK 直发**(GitHub Releases 为主渠道),不走 Google Play:
- Play 新应用强制 AAB + Play App Signing + Data Safety 问卷 + 隐私政策 URL,
  首发的额外流程成本与本工具的受众不匹配;直发 APK 用 C1 自签即完整可用。
- 直发条目固定包含两件产物(缺一不可,GPL 合规见 B2/E5):
  1. `ProResForge-1.0.0.apk`(release 签名);
  2. `ProResForge-source-v1.0.0.zip`(对应源码快照,由 git tag `v1.0.0` 归档产出)。
- 以后如果上架 Play:改走 `:app:bundleRelease` + Play App Signing,versionCode
  重新起算即可,本决策不影响代码库。

## E. 渠道材料

### E1 隐私政策
`PRIVACY.md`(仓库根,随源码快照分发,并发布在下载页):
**不收集、不传输、不上传任何数据**;无 INTERNET 权限(系统级保证);文件访问
全部走 SAF 用户自选;日志仅存本机 `files/logs/app.log`。若改走 Play,Data Safety
表全部选 No(无收集),政策 URL 指向 PRIVACY.md 的发布页副本。

### E2 商店/下载页材料
- **一句话**:ProResForge —— 把 Apple Log / ProRes RAW / DNG 序列转成能直接
  剪辑的 ProRes、H.264/H.265、VP9 的完全离线 Android 转码工具。
- **功能描述**(可直接用于发布页):
  - iPhone 拍摄的 **Apple Log ProRes MOV** → 色彩映射(bt709 / Apple Log 还原)、
    转码为 H.264/H.265 MP4 或 VP9 WebM;
  - **DNG 序列 zip** → ProRes MOV(4096×3072,并行解码,保留 PCM 音轨);
  - ProRes ↔ MP4 双向;含 PCM 音轨的 ProRes 转 MP4 时音轨自动转 AAC(见 F2);
  - 全程**离线**:无网络权限、无上传、无账号;
  - LUT(.cube)前后对比预览;输出目录自选;任务队列可取消、可重跑。
- **截图**:应用内首页(文件+格式选择)、Jobs 任务页(Open/Share)、开源许可页。
  已由模拟器截屏存档:`docs/store-media/`。
- **体积说明(~62MB)**:应用内置整套编解码器二进制——FFmpeg 6.1.6(含 GPL 组件
  x264/x265)、libvpx、LibRaw 0.21.4,全部本地运行,换来的是**零联网、零转码
  服务依赖**。
- **图标**:应用自带(ic_launcher,自适应)。

### E3 内容分级
工具类应用:无广告、无内购、无用户生成内容、不联网、不采集数据。
建议分级:**所有人 / Everyone(ESRB)/ 3+(PEGI)**。Play 问卷按上述如实填写。

## F. 上线后

### F1 反馈与崩溃渠道
- 渠道:发布页 GitHub Issues(或发布页载明的邮箱)。
- 崩溃线索:引导用户开启"显示日志"或直接取 **`Android/data/com.proresforge.app/files/logs/app.log`**
  (应用私有目录;用户需在系统文件选择器中授权该目录,或用 `adb shell run-as
  com.proresforge.app cat files/logs/app.log`)。反馈模板见 E4 末尾的已知限制段。
- 明确**不做**崩溃上报 SDK:无网络权限是产品特性,不为上报开例外。

### F2 已知问题公告(随发布页维护)
1. Android 15 `mediaProcessing` 前台服务 6 小时/日 配额:耗尽后当日无法再启动
   转码(应用会提示,不崩溃),次日自动恢复;
2. 含 PCM 音轨的 ProRes → MP4 会自动把音轨转为 AAC(行为变更,非 bug);
3. 个别播放器对 MP4 内罕见 PCM 封装(`ipcm`)兼容性差——本应用对 MP4 输出已
   自动规避(降级 AAC),如遇外部文件此类问题请转 MOV;
4. 32 位(armeabi-v7a)设备未经广泛测试(见 D4)。
