## 一、已确认的问题

### U-01 浅色模式下状态栏内容完全不可见(高)
现象:系统处于浅色主题时,状态栏区域(0..62px)是纯 #FFFFFF,68040/68040 像素零墨迹 —— 时钟、电量、通知图标全部看不见。
对照证据(同一台设备、同一系统):

| 场景 | 状态栏 0..62px 内容 | 结论 |
|---|---|---|
| 设置 App(浅色) | 背景 #F1F0F7 + 图标墨迹 #606063(2503 px) | 浅色模式本该是深色图标 |
| ProResForge(浅色) | #FFFFFF x68040,0 个非白像素 | 白图标叠白底 = 不可见 |
| ProResForge(深色) | 背景 #121B2E + 白色图标墨迹(1233 px) | 深色下恰好正常 |

定位:`app/src/main/res/values/themes.xml`(`android:windowLightStatusBar=false` 写死;`android:statusBarColor=@color/brand_surface`=#0E1116 与 `navigationBarColor` 在 targetSdk 35 / Android 15 强制 edge-to-edge 后已被忽略)+ `app/src/main/java/com/proresforge/app/MainActivity.kt`(573 B,只 `setContent { ProResForgeTheme { AppNav() } }`,没有 `enableEdgeToEdge`,也没有 insets/系统栏外观处理)+ `app/build.gradle.kts` targetSdk=35。
影响:浅色系统用户看不到时间/电量/通知图标;这不是配色偏好,是功能性信息丢失。
建议:由 Compose 侧接管 —— `enableEdgeToEdge()` + 依 darkTheme 设 `isAppearanceLightStatusBars`(浅色→true);或在 values/、values-night/ 两份 themes.xml 分别写 windowLightStatusBar(true/false),同时不再依赖 statusBarColor。

### U-02 浅色主题主色对比度 3.13:1,不达 WCAG AA(中高,无障碍)
实测:`Theme.kt` LightColors `primary = BrandOrangePressed #E0742A`;设备上 TextButton「Remove」字形像素 = #E0742A。
计算(相对亮度):`#E0742A / 白 = 3.13:1`(橙底白字同样 3.13:1),低于 AA 正文 4.5:1(仅够大字/图形 3:1)。
影响:浅色下所有 TextButton / OutlinedButton 文案(Remove、Show/Hide、Select folder、Logs、Licenses、Clear history、Clear finished、Open、Share、对话框按钮)与填充按钮文字都偏淡;深色下无此问题(primary #FF8A3D / surface 7.33:1,onPrimary #24150A 7.55:1)。
建议:浅色 primary 换成更深的橙(按 4.5:1 反算,约 #A8501A..#B4531A 一档),或 TextButton 标签改用 onSurface/onSurfaceVariant。

### U-03 浅色主题未覆盖 M3 角色,选中 FilterChip 落回基线紫(中)
实测:Home 输出格式卡里选中 chip 容器 = #E8DEF8、标签 = #1D192B(Material3 基线 secondaryContainer/onSecondaryContainer),与品牌橙(#FF7A1A/#E0742A)完全无关。
根因:`Theme.kt` 的 LightColors/DarkColors 只覆盖了 primary/onPrimary/primaryContainer/secondary/background/surface/surfaceVariant/onSurfaceVariant/error/outline 等十余个角色,`secondaryContainer`、`tertiary`、`surfaceContainer*` 等未设置 → 回落 M3 基线调色板。
影响:视觉上出现第三个色系(紫),与"深蓝黑 + 橙"的既定品牌不一致。
建议:补齐 secondaryContainer/onSecondaryContainer/tertiary/surfaceContainer*(或直接给成橙色系)。

### U-04 大字体下顶栏第二行标题被裁切(中)
实测(font_scale 2.0,Home):
- 顶栏区域固定 [63,231] = 168px = 64dp。
- 第一行 title 墨迹 y87..171(85px)。
- 第二行 tagline 墨迹 y200..230 只有 31px(2.0 倍下应约 60px),且 y=226..230 仍有墨迹(141/158/158/149/133 px)、y=231 突变为 0 → 底部整条被硬裁。
- 水平方向也放不下:tagline 节点 [43,180][1079,231],右端顶到屏幕边缘 x=1079(1.0 倍时墨迹只到 x=856);font_scale 1.5 时已顶到 1079。
- 正常 1.0 时两行 bounds 紧贴:title [43,89..163]、tagline [43,163..205],零间距。

定位:`app/src/main/java/com/proresforge/app/ui/AppNav.kt:34-98`(tab0 标题栏 = Column{ app_name titleLarge + app_tagline bodySmall } 塞进默认 TopAppBar 的 64dp)。
建议:大字体场景不要两行挤固定高度 —— 改 MediumTopAppBar(可容纳两行)、或大字体时隐藏 tagline、或把 tagline 移入内容区首个卡片。
### U-05 LUT 卡「体积 / Size」显示 0.0 KB(中)
实测:LUT 卡 `Size = 0.0 KB`(File = Teal & Orange (示例创意))。
证据链:logcat `I HomeVM : LUT 暂存: Teal & Orange (示例创意) size=17`;`app/src/main/java/com/proresforge/app/data/LutFile.kt` 的 `data class StagedLut(path, title, size: Int?, ext)` 类注释明确 size 是 LUT_3D_SIZE/LUT_1D_SIZE(没有则 null),不是文件字节数;而 `app/src/main/java/com/proresforge/app/ui/HomeScreen.kt:533` 用 `formatSize(lut.size?.toLong() ?: 0L)` 把它当字节数 → 17/1024 → "%.1f KB" → 0.0 KB;无 SIZE 头时 size=null → `?: 0L` → formatSize(0) → "-"。
建议:显示网格尺寸(如 17³ / "17 x 17 x 17"),或在 StagedLut 里补真实 byteSize 字段给 UI 用。

### U-06 混合批次丢失 DNG 专属选项,且 zip 帧率档位含无效 ORIG(中)
实测:批次含 1 mov + 1 zip + 1 mov 时,解 raw 质量 / 白平衡 / 色彩映射三组 chip 全部消失,帧率只剩标准档位。
定位:`app/src/main/java/com/proresforge/app/ui/HomeScreen.kt:427` `val zipFacts = firstFile?.facts?.takeIf { it.isDngZip }` —— 只看第一个文件;附带 `FpsMode.standard = listOf(ORIG, F60, F30, F25, F24)` 含 ORIG,而 ORIG(=0)对 zip 是无意义值(应走 `FpsMode.zipOptions = listOf(F24,F25,F30,F48,F50,F60)`)。
建议:zipFacts 判据改 `state.files.any { it.facts?.isDngZip == true }`;批次含 zip 时帧率列表去掉 ORIG(或对 zip 缺省回落 25)。

### U-07 英文文案重复 "about about"(低,但一眼可见)
实测:`DNG sequence zip: 4 frames · 4096×3072. Pick a frame rate (25 by default). Estimated time about about 1 min (…)`。
定位:`app/src/main/res/values-en/strings.xml` —— dng_zip_hint 主句自带 "about",又将 `dng_zip_hint_frames = "about %1$d min"` 作为 %4$s 插入。建议二者留一处。

### U-08 空值渲染:只有标签 / 字面量 "null" / 裸露的 "-"(中低)
- 实测 repro-prores-old.mov 的「Pixel format」行只有标签、没有值:`HomeScreen.kt:298` `FactRow(stringResource(R.string.fact_pixfmt), facts.pixFmt)` 无条件渲染,而 `app/src/main/java/com/proresforge/app/engine/MediaProbe.kt:117` `pixFmt = map["pixfmt"].orEmpty()` 可以为空串。
- 代码层:`HomeScreen.kt:319-322` 色彩行 `"${facts.cspace} / ${facts.cprim} / ${facts.ctrc}"`,而 `MediaProbe.kt:97-99` 三者允许 null → 会打出字面量 `null / null / null`。
- 实测文件行:zip 时长未知时是 `60.0 MB · - · dng`(`HomeScreen.kt:224-236`),裸露的 "-" 出现在信息中间。
建议:值空时不渲染该 FactRow(或显示 "—");色彩行过滤 null 项再 join。

### U-09 LUT 预览在卡片折叠时也照解(中,耗电/卡顿)
定位:`HomeScreen.kt:150-170` 的 `LaunchedEffect(previewKey, state.lutIntensity)` 只要 `firstFile != null` 就跑,`delay(PREVIEW_DEBOUNCE_MS = 250)` 后到 `Dispatchers.IO` 解帧 —— 与 Advanced 是否展开、是否选过 LUT 无关;DNG zip 会解 4096×3072 帧。建议条件加 advancedExpanded(或 state.lut != null)。

### U-10 文件列表非懒加载(低)
定位:`HomeScreen.kt:203` `state.files.forEach { … }` 在单个 LazyColumn item 内逐行渲染(每行含 Remove 按钮)。影响:文件多时全部一起组合,滚动/重组代价随文件数线性上升。建议 `items(state.files, key = { it.id }){ … }`。

### U-11 入队后无去向提示;Jobs 完成卡片不能直接打开结果(中)
实测:点 Start → 权限对话框 → 允许 → Snackbar「Queued 1 job(s)」,页面仍停在 Home,没有"去 Jobs 看进度"的引导;Jobs 页完成卡片只有 Done/Duration/Size/Clear finished,没有 Open/Share(必须切到 History 才有)。建议:Snackbar 加 action 或自动切到 Jobs tab;JobCard 的 DONE 态复用 History 的 Open/Share。

### U-12 完成通知渠道为 LOW,且不深链回 App(中低)
实测(dumpsys):渠道 transcode = IMPORTANCE_LOW、mShowBadge=false、mVibrationEnabled=false;完成通知 category=status、AUTO_CANCEL|ONLY_ALERT_ONCE,extras `android.text="Done: prf-smoke-4f.zip"`。
定位:`app/src/main/java/com/proresforge/app/engine/Notifications.kt`(ensureChannel 抹掉声音/震动/角标;done() 复用同一渠道、contentIntent = ACTION_VIEW 输出文件(mime 兜底 video/*),TranscodeService.kt:96/217/220 调用)。
影响:后台跑完可能完全没被注意到;点通知直接起外部播放器,回不到 App 的任务列表。建议:完成/失败用独立渠道(IMPORTANCE_DEFAULT)并保留角标;contentIntent 指向 App(可在通知里再加"打开文件"动作)。
### U-13 未选中 chip 仅靠 1.62:1 的描边区分(WCAG 1.4.11)(中低)
实测:未选中 FilterChip 在白色卡片上填充也是 #FFFFFF,只剩描边 #C6CBD8 → 对比度 1.62:1(深色:outline #33425F / surface #121B2E = 1.71:1),低于"非文本 UI 组件 3:1"。建议:加深 outline(浅色约 #6B7280 档)或给未选中 chip 一个可辨填充(surfaceVariant)。

### U-14 通知理由对话框"点外部/返回"= 静默跳过授权并开转(低)
定位:`HomeScreen.kt:651-675`,`onDismissRequest = ::startWithoutNotificationPermission`(653 行)。点对话框外部或按返回键都会直接开始转码。建议:onDismissRequest 仅关闭对话框(不启动),让用户明确点「Not now」才算跳过。

### U-15 卡片标题与按钮文案重复(低)
实测:「Pick files」卡片标题 = 按钮「Pick files」;「LUT」卡片标题 = 按钮「LUT」(en;zh 为「LUT 滤镜」)。建议标题用名词(如 Input files / LUT filter),动作归按钮。

### U-16 大字体下 FactRow 标签与值紧贴(低)
定位:`app/src/main/java/com/proresforge/app/ui/components.kt:139` 标签列 `widthIn(min = 84.dp)` 且无右间距;font_scale 1.5 时实测「Pixel format」结束于 x=377,值「rgb48le」从 x=377 开始(零间隔)。建议标签后加 8dp 或改上下两行布局。

### U-17 许可证弹窗:近乎全屏 + 整篇单块文本 + Markdown 记号原样(低)
定位:`app/src/main/java/com/proresforge/app/ui/LicensesScreen.kt`(`DialogProperties(usePlatformDefaultWidth = false)` + `Column(Modifier.fillMaxSize())`);设备实测:正文是单个 Text(节点 [95,422][984,2230]),NOTICE 全文含 # / | 表格等 Markdown 记号原样显示;Close 按钮 48dp 正常。建议:改为全屏页面,正文按段/按行 split 进 LazyColumn,至少去掉标题/列表记号。

### U-18 History 顶部操作行随滚动消失(低)
定位:`HistoryScreen.kt` 里「History」+ Logs/Licenses/Clear history 三个按钮是 LazyColumn 的第一个 item,非 sticky。建议移到 TopAppBar 或 pinnedHeader。

## 二、复核为正常(排除的误报)

- 「17px(≈6.5dp)高的可点击节点出现在 Advanced 卡片头」:是 LazyColumn 视口把卡片头按钮裁掉的滚动裁剪产物,不是布局错误。
- 「Licenses 弹窗一个 item 里两个 Text 会重叠」:不成立 —— 标题 [95,359..422] 与正文 [95,422..2230] 正确堆叠、无重叠。
- 文本重叠/越界/0 尺寸:leaf-node 扫描在 font_scale 1.0(History,20 个节点)、1.5、2.0(Home)下均未发现重叠或越界(唯一超界即 U-04 的 tagline 宽度)。
- 触摸目标:已测屏幕上的 Cancel / Open / Share / Close / 对话框按钮 / 通知对话框按钮实测均 ≥48dp(48dp = 126px)。
- 系统栏与顶栏色差:浅色 #FFFFFF vs #FFFFFF、深色 #121B2E vs #121B2E,无接缝;深色导航条胶囊(#EEEDEE on #211F26)、浅色(#615F63 on #F3EDF7)可见。
- LUT 预览瓦片(Original/Graded 各占 1/2 宽、16:9)工作正常;强度滑条显示 100%;Jobs/History 的双标签、尺寸、时长、错误红字、进度行均按源码预期渲染。
- 深色主题整体对比度:onSurface 14.5:1、onSurfaceVariant 9.5:1、error 6.19:1,均达标。

## 三、建议修复顺序

1. U-01(浅色状态栏不可见)—— 功能性问题,一次改动覆盖两个主题。
2. U-03 + U-02(补齐浅色 M3 角色 + primary 对比度)—— 同一处 Theme.kt,顺手一起改。
3. U-04(大字体顶栏裁切)—— 影响可达性设置用户。
4. U-06 / U-05 / U-08(信息正确性:混合批次、LUT 体积、空值)。
5. U-11 / U-12 / U-09(流程与资源:入队去向、完成通知、预览白耗)。
6. U-07 / U-10 / U-13…U-18(文案、懒加载、描边、对话框语义、布局细节)。
