## 首轮 UI 整改计划

### 1. 收紧开始转码的前置状态
- 修改 `app/src/main/java/com/proresforge/app/ui/HomeViewModel.kt`：将“已选择文件且全部探测成功”与“已选择输出目录”统一纳入可开始条件，避免按钮看似可用、点击后才报错。
- 修改 `HomeScreen.kt`：在开始按钮附近显示明确的阻塞原因；未选目录时按钮保持禁用，同时保留输出目录卡片上的红色提示和“选择目录”操作。
- 对应补充中英文 strings，确保空文件、探测中、未选目录三类状态不会混用。

### 2. 延后通知权限请求到首次转码
- 移除 `MainActivity.kt` 启动即请求 `POST_NOTIFICATIONS` 的逻辑。
- 将请求移动到转码页的“开始转码”动作附近：首次真正开始后台任务时才触发，并在系统权限框前显示简短用途说明；用户拒绝通知时仍继续转码，不阻塞队列。
- 保留进程内“一次只问一次”保护，避免旋转、切 Tab 或重新组合时重复弹窗。
- 维持 Manifest 权限和现有通知服务逻辑不变。

### 3. 缩短主转码页的信息路径
- 修改 `HomeScreen.kt`：保留文件选择、媒体摘要、输出格式、分辨率/帧率、输出目录和开始操作作为主流程；将 LUT、音频及低频参数放入可展开的“高级设置”区域，默认不抢占首屏。
- 对 DNG zip 保留必要的解 raw、白平衡、色彩映射选项，但只在检测到 DNG zip 时呈现，避免普通视频看到不相关参数。
- 当输出格式为 ProRes 时，不再展示会被忽略的“高/中/低”伪可调控件，改为显示固定的 ProRes 422 HQ 说明；其他格式继续显示质量选择。
- 保持现有 `JobSpec`、设置持久化和 LUT 预览逻辑不变，只调整可见性与层级。

### 4. 修正任务终态的进度表达
- 修改 `components.kt` / `JobsScreen.kt`：取消或失败的任务不再显示“100%”进度条，改为状态文本和错误信息；运行中/排队中继续显示阶段、帧数和进度；完成任务显示明确的完成状态与产物信息。
- 不修改 `JobBus` 的状态机和 `TranscodeService` 的取消竞态处理，避免触碰已验证的核心逻辑。

### 5. 保护历史记录操作
- 修改 `HistoryScreen.kt`：点击“清空历史”先弹出确认对话框，确认后才调用现有 `JobStore.clear()`；取消或返回不产生副作用。
- 增加中英文确认标题、说明、取消和确认文案。
- 本轮不实现历史任务自动重试：`HistoryItem` 当前仅保存输出 URI 和展示信息，没有可靠的输入 URI，自动重试会导致无法恢复源文件或行为不确定。

### 6. 轻量统一导航视觉层级与可用性
- 修改 `AppNav.kt`：转码页保留产品名和副标题，任务页/历史页使用更简洁的页面标题，减少重复品牌文案占用垂直空间。
- 统一选中态和主操作的颜色语义，保留现有橙色品牌主按钮，不改变深色/浅色主题的整体配色。
- 为新增的折叠、确认和权限说明控件补齐 Compose 可访问性语义和内容描述。

### 7. 验证
- 运行 `testDebugUnitTest` 和 `assembleDebug`，确认既有数据/引擎测试不受影响。
- 在现有 Android 模拟器安装并运行 APK，验证：启动不立即弹通知权限；首次点击开始时才请求；未选目录时按钮禁用且提示明确；ProRes 质量项不再误导；取消任务不显示 100%；清空历史需要确认；高级设置折叠/展开和底部导航无遮挡。
- 保留现有源码改动，不删除用户已有的构建产物或测试样本。
